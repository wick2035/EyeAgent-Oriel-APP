## 1. 项目约定与现有规范

### 1.1 基础配置

| 配置项 | 值 | 来源文件 |
|--------|-----|---------|
| Base URL | `http://127.0.0.1:8081` | `utils/config.js` |
| 请求超时 | 30000ms | `utils/api/request.js` |
| 鉴权方式 | Sa-Token（Header: `satoken`） | `utils/api/request.js` |
| WebSocket | `ws://127.0.0.1:8081/ws/app/notify` | `utils/websocket.js` |

### 1.2 统一响应格式

所有已实现的接口均遵循以下响应信封：

```json
{
  "code": 200,
  "msg": "ok",
  "data": { ... }
}
```

**错误码约定**：
- `200` — 成功
- `401` — 未授权（前端自动清除 token 并跳转登录页）
- `404` — 资源不存在
- `40901` — 业务冲突（如 E2EE 会话已存在）
- `500` — 服务器错误

### 1.3 分页约定

**请求参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `pageNum` | number | 页码，从 1 开始 |
| `pageSize` | number | 每页数量，默认 10 |

**响应结构**（参考已有的 `page-hospital-info`、`page-conversation` 接口）：

```json
{
  "code": 200,
  "data": [ ... ],
  "total": 100,
  "pages": 10,
  "pageNum": 1
}
```

> 或者也可以采用下面的嵌套格式（两种均可，但需统一）：
> ```json
> {
>   "code": 200,
>   "data": {
>     "list": [ ... ],
>     "total": 100,
>     "page": 1,
>     "pageSize": 10,
>     "hasMore": true
>   }
> }
> ```

### 1.4 金额约定

订单模块使用 **分 (cents)** 为单位。例如 `price: 5800` 表示 ¥58.00。

### 1.5 已实现的 API 路径前缀

| 前缀 | 功能域 |
|------|--------|
| `/api/app/base/*` | 基础功能（登录、注册、预约、患者信息、通知） |
| `/api/app/agent/*` | AI 问诊对话 |
| `/api/app/chat/*` | E2EE 加密医患对话 |
| `/api/app/video/*` | 视频会诊 |
| `/api/app/extra/*` | 扩展功能（用药提醒、手术进度） |
| `/api/user/*` | 用户资料 |
| `/api/file/*` | 文件下载 |

### 3.2 获取资讯详情

```
GET /api/app/news/detail/{id}
```

**请求参数** (Path):

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | number | 是 | 文章 ID |

**响应**: 与列表中单条数据结构一致，额外包含 `content` 字段（HTML 富文本）。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "id": 1,
    "title": "...",
    "content": "<h2>流感高发季节来临</h2><p>每年秋冬季节...</p>...",
    "...": "（其他字段同列表）"
  }

```

**业务逻辑**:
- 每次请求应自增 `viewCount`（浏览量 +1）
- `content` 为 HTML 富文本，可包含 `<h2>`、`<h3>`、`<p>`、`<ul>`、`<ol>`、`<blockquote>`、`<img>`、`<table>` 等标签

### 3.13 建议数据库表

```sql
-- 资讯分类
CREATE TABLE news_category (
  id VARCHAR(32) PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  icon VARCHAR(50),
  sort_order INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 资讯文章
CREATE TABLE news_article (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200) NOT NULL,
  summary VARCHAR(500),
  content LONGTEXT,           -- HTML 富文本
  cover VARCHAR(500),
  images JSON,                -- 图集图片 URL 数组
  video VARCHAR(500),
  type ENUM('article','gallery','video') DEFAULT 'article',
  category_id VARCHAR(32),
  source VARCHAR(100),
  author VARCHAR(50),
  author_title VARCHAR(50),
  publish_time DATETIME,
  view_count INT DEFAULT 0,
  like_count INT DEFAULT 0,
  comment_count INT DEFAULT 0,
  status TINYINT DEFAULT 1,   -- 1=已发布, 0=草稿, -1=下架
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (category_id) REFERENCES news_category(id)
);

-- 文章标签 (多对多)
CREATE TABLE news_tag (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE news_article_tag (
  article_id BIGINT,
  tag_id BIGINT,
  PRIMARY KEY (article_id, tag_id)
);

-- 用户行为（点赞/收藏）
CREATE TABLE news_user_action (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id VARCHAR(64) NOT NULL,
  article_id BIGINT NOT NULL,
  action_type ENUM('like','favorite') NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_user_article_action (user_id, article_id, action_type)
);

-- 评论
CREATE TABLE news_comment (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  news_id BIGINT NOT NULL,
  user_id VARCHAR(64) NOT NULL,
  parent_id BIGINT DEFAULT NULL,         -- NULL=主评论，非NULL=回复
  reply_to_user_id VARCHAR(64),
  reply_to_nickname VARCHAR(50),
  content TEXT NOT NULL,
  like_count INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_news_id (news_id),
  INDEX idx_parent_id (parent_id)
);

-- 评论点赞
CREATE TABLE news_comment_like (
  user_id VARCHAR(64),
  comment_id BIGINT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, comment_id)
);

-- 阅读历史
CREATE TABLE news_read_history (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id VARCHAR(64) NOT NULL,
  article_id BIGINT NOT NULL,
  read_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id)
);
```
