# 登录状态验证测试指南

## 测试准备

1. 确保应用已编译并运行
2. 准备测试账号（有效的用户名和密码）
3. 确保能访问后端API（http://1.117.233.43:8081）

## 测试场景

### 场景1：正常登录流程

**测试步骤：**
1. 启动应用，应该停留在登录页
2. 输入正确的用户名和密码
3. 点击登录

**预期结果：**
- ✅ 登录成功，显示成功提示
- ✅ 自动跳转到首页（TabBar首页）
- ✅ WebSocket连接建立并认证成功（查看控制台日志）
- ✅ 能正常使用各个功能页面

**验证方法：**
```javascript
// 在控制台查看日志应包含：
// "Token验证成功，进入应用"
// "WebSocket连接已建立"
// "WebSocket认证成功"
```

3. 重新启动应用

**预期结果：**
- ✅ 应用启动时自动验证token
- ✅ 验证成功后直接进入首页


### 场景3：Token过期（401）

**测试步骤：**

**方式A - 应用启动时检测：**
1. 手动删除后端的token或等待token过期
2. 重新启动应用

**方式B - API请求时检测：**
1. 在已登录状态下
2. 手动删除后端的token
3. 在应用中触发任意API请求（如刷新页面、查看个人资料等）

**预期结果：**
- ✅ 显示Toast提示："登录已过期，请重新登录"
- ✅ 清除本地所有登录状态（token、用户信息）
- ✅ 断开WebSocket连接
- ✅ 1.5秒后自动跳转到登录页
- ✅ 清除通知状态

**验证方法：**
```javascript
// 控制台日志应包含：
// "Token验证失败" 或 "检测到401未授权，清除登录状态"
// 检查本地storage，token应该被清除
```

### 场景4：网络错误处理

**测试步骤：**
1. 确保有token但未过期
2. 断开设备网络（开启飞行模式或断开WiFi）
3. 重新启动应用

**预期结果：**
- ✅ 显示弹窗："网络连接失败"
- ✅ 弹窗内容："无法验证登录状态，请检查网络连接"
- ✅ 提供两个选项：
  - "重试" - 重新验证token
  - "退出登录" - 清除状态并跳转登录页

**测试子场景A - 用户选择重试：**
1. 点击"重试"按钮
2. 保持网络断开 - 应再次显示弹窗
3. 恢复网络连接后点击"重试"
4. 应该验证成功并进入应用

**测试子场景B - 用户选择退出：**
1. 点击"退出登录"按钮
2. 应清除登录状态并跳转到登录页

**验证方法：**
```javascript
// 控制台日志应包含：
// "Token验证异常:" + 错误信息
// "用户选择重试验证" 或 "用户选择退出登录"
```

### 场景8：登录后跳转回原页面（可选功能）

**当前实现：**
路由守卫已预留redirect参数功能，但登录页暂未实现自动跳转。

**如需启用此功能：**
在 `pages/login/login.vue` 的登录成功回调中添加：
```javascript

uni.reLaunch({ url: redirect })
```

## 性能验证

### 路由守卫性能
- 每次路由跳转拦截耗时应 < 10ms
- 仅读取本地storage，无网络请求

### API验证性能
- Token验证API响应时间应 < 500ms
- 不阻塞应用启动流程

### 用户体验验证
- 所有跳转都有Toast提示，避免突兀
- 延迟跳转时间：1.5秒（给用户阅读提示的时间）
- WebSocket连接异步进行，不阻塞页面进入

## 常见问题排查

### 1. 路由守卫不生效
**检查：**
- `main.js` 是否正确导入并调用 `initRouteGuard()`
- 控制台是否有 "路由守卫已初始化" 日志

### 2. Token验证一直失败
**检查：**
- 网络连接是否正常
- API地址是否正确（http://1.117.233.43:8081）
- 后端服务是否运行
- Token是否确实已过期

### 3. WebSocket连接失败
**检查：**
- Token是否有效
- WebSocket URL是否正确（ws://1.117.233.43:8081/ws/app/notify）
- 防火墙或网络是否限制WebSocket连接

### 4. 跳转登录页后立即被路由守卫拦截
**检查：**
- 登录页路径是否在白名单中（/pages/login/login）
- `clearLoginState()` 是否正确清除了token

## 技术细节总结

### 验证流程
```
应用启动 
  → 初始化用户状态（从storage恢复）
  → 检查isLoggedIn() 
  → 调用API验证token 
  → 验证成功 → 异步连接WebSocket → 进入首页
  → 验证失败（401） → Toast + 跳转登录
  → 网络错误 → 弹窗选择（重试/退出）
```

### 路由守卫流程
```
页面跳转 
  → 拦截器检查目标URL 
  → 白名单？→ 放行
  → 检查本地token 
  → 存在 → 放行
  → 不存在 → 重定向登录页
```

### 401处理流程
```
API请求返回401 
  → clearLoginState() 
  → 清除token + 用户信息 + WebSocket + 通知
  → Toast提示 
  → 延迟1.5秒 
  → reLaunch到登录页
```
